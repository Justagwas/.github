# Contributing

Thank you for taking the time to improve a Justagwas project.

Each repository describes its purpose, supported environment, and current behavior in its README and documentation. Read those resources before proposing a change, and follow any repository-specific contributing guide when one is present.

## Before opening an issue

1. Confirm that the issue applies to the latest release or current default branch.
2. Read the available documentation and troubleshooting guidance.
3. Search existing issues to avoid duplicates.
4. Remove private information from logs, screenshots, configuration, and example files.

Use the appropriate issue form and provide enough context for another person to understand and reproduce the problem.

## Proposing a change

A useful proposal explains:

- The problem being solved.
- The result the user should experience.
- Any alternatives already considered.
- Compatibility, safety, privacy, or maintenance implications.

## Pull requests

1. Fork the repository and create a focused branch.
2. Follow the project's existing structure and writing style.
3. Keep unrelated changes in separate pull requests.
4. Test the affected behavior in the supported environment.
5. Update documentation when commands, configuration, behavior, or user-facing text changes.
6. Open a pull request with a concise explanation of what changed and why.

Avoid committing credentials, private files, generated secrets, local settings, build output, or unrelated formatting changes.

## Review

A contribution may require revision before it can be accepted. Review considers correctness, scope, maintainability, user impact, compatibility, documentation, and safety where applicable.

Submitting a contribution does not guarantee that it will be merged, but every focused and well-documented proposal is welcome.
